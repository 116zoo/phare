Lubliner ART — audit SEO & visibilité IA

Le site est lisible par les robots et ses principales pages répondent en 200. Les entités JSON-LD sont maintenant bien présentes. La découverte reste fragilisée par l’absence de sitemap racine et par une configuration de génération des sitemaps qui ne suit pas la stratégie d’URL actuelle.

À corriger dans cet ordre : rétablir /sitemap.xml, aligner next-sitemap.config.cjs sur les préfixes fr/en, compléter les métadonnées Open Graph des pages éditoriales, sortir les pages de recherche des sitemaps, puis enrichir les faits citables avec les coordonnées et les informations d’activité validées par le dirigeant.

Les cinq priorités

Critique

1. Sitemap racine absent

/sitemap.xml renvoie 404. Les quatre sitemaps directs existent : pages/posts en français et en anglais. Un crawler qui cherche le point d’entrée standard ne trouve donc rien.

Impact élevé · effort petit à moyen

<!-- index recommandé à /sitemap.xml -->
<sitemapindex xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <sitemap><loc>https://www.example.com/pages-sitemap.xml</loc></sitemap>
  <sitemap><loc>https://www.example.com/posts-sitemap.xml</loc></sitemap>
  <sitemap><loc>https://www.example.com/en/pages-sitemap.xml</loc></sitemap>
  <sitemap><loc>https://www.example.com/en/posts-sitemap.xml</loc></sitemap>
</sitemapindex>

Remplacer le domaine d’exemple par le domaine de production. Ne pas publier les URLs localhost.

Critique

2. Préfixes incohérents dans next-sitemap

Le runtime utilise le français à la racine et l’anglais sous /en. La configuration next-sitemap.config.cjs inverse ces préfixes pour les sitemaps additionnels.

Impact élevé · effort petit

const additionalSitemaps = LOCALES.flatMap((locale) => {
  const prefix = locale === 'fr' ? '' : `/${locale}`
  return [
    `${SITE_URL}${prefix}/pages-sitemap.xml`,
    `${SITE_URL}${prefix}/posts-sitemap.xml`,
  ]
})
Attention

3. Open Graph incomplet sur les pages dédiées

La page d’accueil émet og:url. Les pages vérifiées /presentation, /partenaires et /un-homme-de-radio n’en émettent pas dans le HTML brut. Plusieurs routes ont un titre/description mais pas de bloc Open Graph propre à la page.

Impact moyen · effort petit

import { mergeOpenGraph } from '@/utilities/mergeOpenGraph'

return {
  title,
  description,
  alternates: { canonical },
  openGraph: mergeOpenGraph({ title, description, url: canonical }, 'Lubliner ART'),
}
Attention

4. Recherche et index de posts dans le sitemap

Le sitemap de pages liste /search et /posts. La recherche interne est rarement une page destinée à l’indexation et peut créer des URLs faibles ou redondantes. Décider explicitement si /posts est une page éditoriale indexable.

Impact moyen · effort petit

exclude: [
  '/search',
  '/search/*',
  // ajouter '/posts' seulement si l’index éditorial n’est pas une page cible
]
Attention

5. Faits citables encore incomplets

llms.txt décrit bien les chemins créatifs et les pages clés, mais ne fournit pas dans la section de contact un téléphone, un e-mail, des horaires ou une zone d’intervention. Le JSON-LD contient une adresse parisienne ; elle doit être confirmée et reprise de façon cohérente dans les pages visibles et les fiches tierces.

Impact élevé pour la fiabilité · effort moyen

Aucune donnée ne doit être inventée. À compléter uniquement avec les coordonnées, horaires, services et zones validés par Jean-Paul Lubliner.

Limites et contrôle suivant

Les assistants externes ne peuvent pas tester honnêtement un site limité à localhost : aucun test de recommandation ou de citation IA n’est donc déclaré. La présence Google Business Profile, les annuaires, les avis et les citations locales n’ont pas été vérifiés depuis cet environnement.

Après correction, refaire le contrôle dans 30 jours sur le domaine de production, avec vérification des URLs canoniques, des sitemaps, des faits de contact et des sources tierces.
